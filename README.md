# LNPG-2026-TAD-Banco-GabrielFranca

Neste projeto, desenvolvi um pequeno sistema bancário utilizando os conceitos de Tipos Abstratos de Dados (TADs), encapsulamento, relacionamentos entre objetos e subprogramas. O sistema foi dividido em três classes principais: Cliente, Banco e ContaBancaria. Cada uma delas representa uma entidade importante de um sistema bancário e possui responsabilidades específicas dentro da aplicação.

Para evitar repetição de código, criei alguns subprogramas de validação dentro das próprias classes. Na classe Cliente, por exemplo, foram criados métodos como validar_nome, validar_cpf, validar_telefone, validar_email e limpar_numeros. Já nas classes Banco e ContaBancaria, utilizei métodos para validar números positivos. Optei por criar esses subprogramas porque algumas verificações eram realizadas mais de uma vez ao longo do código. Dessa forma, consegui reduzir duplicações e tornar a implementação mais organizada e fácil de manter. Caso alguma regra precise ser alterada futuramente, a modificação poderá ser feita diretamente no método responsável pela validação.

Os relacionamentos entre Banco, Cliente e ContaBancaria foram implementados por meio da associação entre objetos. A classe ContaBancaria possui um atributo que armazena o cliente titular da conta e outro atributo que armazena o banco ao qual a conta pertence. Isso garante que cada conta esteja associada a exatamente um cliente e a exatamente um banco, conforme definido na especificação. A classe Banco mantém uma lista contendo todas as contas cadastradas, permitindo adicionar, remover, buscar e listar contas. Também foi possível representar a situação em que um mesmo cliente possui mais de uma conta bancária.

As regras de negócio que exigiram mais atenção foram as relacionadas às validações dos dados e às operações financeiras. Foi necessário verificar corretamente o tamanho mínimo do nome, a quantidade de dígitos do CPF e do telefone, além da presença do caractere "@" no e-mail. Também foi importante implementar as regras de depósitos e saques, garantindo que apenas valores válidos fossem aceitos e que o saldo da conta não fosse alterado quando uma operação inválida fosse realizada.

O conceito de encapsulamento foi utilizado por meio dos métodos responsáveis por acessar e modificar os dados dos objetos, evitando que informações importantes fossem manipuladas de maneira inadequada. Já a abstração foi aplicada ao representar elementos do mundo real, como clientes, bancos e contas bancárias, utilizando classes que armazenam apenas as características necessárias para o funcionamento do sistema. Com isso, foi possível construir uma solução organizada, modular e alinhada aos conceitos estudados na disciplina.
